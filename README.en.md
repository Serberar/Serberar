### Principles

1. **Understand before writing.** The smallest change that solves the whole problem.
2. **Test behaviour.** A test is worth the failure it prevents, not the coverage it adds.
3. **Fail clearly.** Log the full error and tell the user what they can do.
4. **Automate what repeats.** Tests, build and release on every change.
5. **Document just enough.** A README that gets you running and explains why.
